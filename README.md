# hammerspoon-scroll-bounce-filter

노치(단계식) 마우스 휠의 스퓨리어스 역틱("아래로 굴리는데 순간 위로 톡" 튐)을 [Hammerspoon](https://www.hammerspoon.org/) eventtap으로 억제하는 필터. **v10 — 정착창 검증 디바운서 (settling-window glitch filter)**: 로터리 엔코더 글리치 필터링의 표준 기법(integrating/verifying debouncer)을 스크롤 이벤트 스트림에 적용. 방향 상태·질량 모델 없음, 판별축은 **인접성 하나**.

## 왜 이 구조인가

실측으로 확정된 제약 (v1~v6 시절 260~2240틱 트레이스 + 2026-08-31 · 2026-09-01 재실측):

1. 튐 틱과 진짜 반전 틱은 **이벤트 수준에서 바이트 동일** (magnitude·fixedPt·타이밍·phase 메타 전 축 분포 겹침 — 노치 휠은 phase 메타데이터가 전부 0). per-tick 분류는 정보 부재로 불가능.
2. 스퓨리어스는 mag-1 단독 틱뿐 아니라 **가속 붙은 역방향 클러스터**(합 11까지 관측)로도 온다 → run-길이 카운트(v3~v7의 flipTicks) 판별은 반증됨.
3. **같은 방향 연속 스크롤도 버스트 간 gap이 354~928ms** → "N ms 침묵 = 제스처 끝" 하드 컷오프(v5 gap-gating, v8 하드 윈도우)는 성립하지 않는다.
4. 방향 상태를 "마지막 확정 1비트"로 들고 있으면(v7까지 전부) 한 번의 오확정이 **역-잠금**(진짜 틱이 억제되고 스퓨리어스가 통과)을 만든다.
5. **속도/질량류 모델(칼만 velocity-gating, IMM 포함)은 구조적으로 오분류한다** (2026-09-01 트레이스 110행): 사람의 진짜 반전은 직전 틱과 205~532ms 떨어져 오는데, 이는 같은 방향 버스트 gap(354~928ms)과 **겹친다**. 감쇠 시정수를 버스트 gap에 버티게 잡으면 사람 반전이 반드시 "고속 중 역틱"으로 오분류된다. v8.1(감쇠 질량 다수결 = 1차원 velocity-gating)이 이걸로 죽었다 — 16초 교대 스크롤 재현에서 **사람 입력 55라인을 absorb로 폐기**(최대 +14 버스트 통째 증발) + 보류분 9~13라인 일괄 덤프 5회.

이 제약 하에서 남는 유일한 판별축은 **인접성**이다: 튐은 기계적 리바운드라 **항상 실 모션에 인접**(4ms 간격 클러스터, 복귀 28~90ms), 사람 반전은 직전 틱과 205ms+ 떨어져 온다.

## v10 구조 (규칙 3줄)

- **같은 방향 틱 → 즉시 통과.**
- **역방향 틱, 직전 통과 틱과 gap ≥ `guardMs`(120) → 즉시 통과** — 사람 반전, 지연 0.
- **역방향 틱, gap < `guardMs` → 정착창 보류** (delta 0화 + 버퍼 적립):
  - `holdMs`(100) 내 원방향 복귀 → 보류분 폐기 = 튐이 화면에 아예 안 나감.
  - 복귀 없이 `holdMs` 경과 → 타이머가 버퍼를 이벤트 copy에 실어 post — 사람 빠른 반전, **무손실**, 지연 ≤100ms.
- post 재진입 echo 가드(재진입 실측 ~3ms): 직전 post delta와 일치하는 재진입은 무가공 통과.
- 트랙패드(연속 pixel scroll)는 건드리지 않는다. 이벤트 삭제(`return true`)는 이 환경에서 무효 → delta 0화(setProperty)로 억제.

**검증**: 결정론 오라클 5/5(인접 튐 흡수 / 즉시 반전 통과 / 정착창 무손실 방출+echo / 가속 클러스터 흡수 / 백스톱 합산) + **실사용 트레이스 재생**(`v10_replay.py`): v8.1/v9의 유실 55라인 → 18라인(잔여는 측정된 튐 시그니처와 동일 형태), 진짜 반전 13건 전부 지연 0.

트레이드오프(정직): 직전 틱과 ≥`guardMs` 떨어져 도착하는 gap-스퓨리어스는 즉시 통과된다(1~3라인 blip). "방향 정확성 > 튐 억제" 우선순위의 의도된 수용 — 이걸 막으려던 질량 기계가 사람 입력을 먹는 비용이 더 컸다(제약 5). 잔여 한계: 인접 반전 후 100ms 내 원방향으로 되돌아오는 "빠른 왕복 위글"(<220ms)은 튐과 동일 시그니처라 흡수된다(정보 부재 — 환원 불가). 근본 소멸은 마우스(엔코더) 교체뿐이다.

| `SCROLL_BOUNCE_FIX.md` | v1→v10 도달 경로, 실패 이력, 측정으로 확정된 사실 |
| `SCROLL_BOUNCE_HANDOFF.md` | 현재 상태 · 재현 레시피 · 결정론 오라클 스니펫 · 튜닝 노브 |
| `v10_replay.py` + `trace-2026-09-01-v9-alternating.log` | 실사용 트레이스 재생 시뮬 — v10 설계 근거이자 튜닝/회귀 검증 하네스 |
| `scroll_harness.py` | (v6 시절) 결정 상태머신 파이썬 포팅 — **현행 로직과 불일치, 참고용** |

## 사용

`scroll_bounce_filter.lua` 내용을 `~/.hammerspoon/init.lua`에 추가하고 Hammerspoon reload. 트랙패드(연속 pixel scroll)는 건드리지 않는다.

결정론 검증(실 이벤트 불요): `scrollProcessDeltas(line, fp, pt, nowSeconds)` / `scrollTimerCheck(nowSeconds)` 직접 호출 — 스니펫은 `SCROLL_BOUNCE_HANDOFF.md`.
