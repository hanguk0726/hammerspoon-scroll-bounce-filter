# hammerspoon-scroll-bounce-filter

노치(단계식) 마우스 휠의 스퓨리어스 역틱("아래로 굴리는데 순간 위로 톡" 튐)을 [Hammerspoon](https://www.hammerspoon.org/) eventtap으로 억제하는 필터. **v8.1** — 지배 방향 감쇠 질량 다수결(dominant-direction decayed mass) + 역방향 보류-확인(hold & confirm).

## 왜 이 구조인가

실측으로 확정된 제약 (v1~v6 시절 260~2240틱 트레이스 + 2026-08-31 재실측):

1. 튐 틱과 진짜 반전 틱은 **이벤트 수준에서 바이트 동일** (magnitude·fixedPt·타이밍·phase 메타 전 축 분포 겹침 — 노치 휠은 phase 메타데이터가 전부 0). per-tick 분류는 정보 부재로 불가능.
2. 스퓨리어스는 mag-1 단독 틱뿐 아니라 **가속 붙은 역방향 클러스터**(합 11까지 관측)로도 온다 → run-길이 카운트(v3~v7의 flipTicks) 판별은 반증됨.
3. **같은 방향 연속 스크롤도 버스트 간 gap이 354~928ms** → "N ms 침묵 = 제스처 끝" 하드 컷오프(v5 gap-gating, v8 하드 윈도우)는 성립하지 않는다.
4. 방향 상태를 "마지막 확정 1비트"로 들고 있으면(v7까지 전부) 한 번의 오확정이 **역-잠금**(진짜 틱이 억제되고 스퓨리어스가 통과)을 만든다.

이 제약 하의 v8.1 구조:

- **지배 방향 = 최근 통과 틱 질량(|delta| 합)의 지수 감쇠 다수결** (`domMass·e^(-Δt/τ)`, τ=350ms). 1비트가 아니라 질량이므로 오판이 나도 다음 실 틱들이 즉시 되받아 자기교정 — 역-잠금이 구조적으로 소멸한다 (제약 4의 해소).
- **역방향 틱은 즉시 내보내지 않고 보류**(delta 0화 + 원본 이벤트 copy 보관). 지배쪽 틱이 다시 오면 보류분 폐기 = 튐이 화면에 아예 안 나감 (오판 복귀는 실측 28~90ms 내 도착).
- **진짜 반전 확정 2경로**: ① 미드스트림 — 보류 질량 > 2.0×감쇠 질량 **AND** 역방향 지속 ≥150ms (클러스터는 ~30ms라 미달 → 제약 2의 해소) ② 소진 — 감쇠 질량 < 1.0 && 보류 ≥100ms → 보류 delta를 이벤트 copy에 실어 post. 활발한 스크롤 뒤 소진까지 ~1.2s 침묵이 필요해 버스트 간 gap에는 절대 발동하지 않는다 (제약 3의 해소).
- **post 재진입 echo 가드**: post한 이벤트는 앱에 도달하고 eventtap에도 ~3ms 뒤 재진입한다(2026-08-31 실측 — 이전 "post 무효" 프로브 결론은 관측 지점 오류로 반전). 직전 post delta와 일치하는 재진입은 무가공 통과시켜 질량 이중 적립을 막는다.

트레이드오프(정직): 진짜 반전의 첫 반응이 미드스트림 ~0.2–0.4s, 단독 반전 1노치는 소진 대기(~0.4–1.2s)만큼 지연된다. 잔여 한계: 제스처 "마지막" 틱이 튐이고 후속 틱이 없으면 소진 시점에 늦은 역점프 1회(단독 의도 반전과 동일 바이트 — 환원 불가). 근본 소멸은 마우스(엔코더) 교체뿐이다.

| `scroll_harness.py` | (v6 시절) 결정 상태머신 파이썬 포팅 — **v8.1 로직과 불일치, 참고용** |

## 사용

`scroll_bounce_filter.lua` 내용을 `~/.hammerspoon/init.lua`에 추가하고 Hammerspoon reload. 트랙패드(연속 pixel scroll)는 건드리지 않는다.

결정론 검증(실 이벤트 불요): `scrollProcessDeltas(line, fp, pt, nowSeconds)` / `scrollTimerCheck(nowSeconds)` 직접 호출 — 스니펫은 `SCROLL_BOUNCE_HANDOFF.md`.
